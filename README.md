## 2026-10-16：B 键单击切换夹爪

当前 B 控制：按一下闭合，松开保持，再按一下打开，再按又闭合。
食指扳机仍为按住移动、松开暂停，机械臂暂停时 B 可独立操作夹爪。
长按 B 只切换一次；按下需稳定 60 ms，并对实际松开做去抖。
若合并快照中只看到释放计数增加，重新对当前按下去抖，不在释放时动作。
启动、重新启用时已经按住 B 不执行，需松开再按；掉线、停止不自动开爪。

切换依据依次为最新排队目标、正在发送的目标、最近成功下发目标；
首次没有下发记录时才使用 0.75 秒以内的实测开度，以配置开/合中点判断。
因此刚启动时若夹爪已闭合，第一次有效点击会打开。夹住物体无法到达零开度时，
仍依据已成功下发的闭合目标判断下一次为打开。取消/超时且未下发的闭合不算成功闭合。
界面明确开/合按钮会同步影响下一次 B 切换。SDK 失败后禁止继续自动切换，
检查原因后可用界面明确开/合恢复；已排队的 B 指令也要重新核验故障状态。

GUI 提示已同步。高级设置中的 A 兼容模式仍为按住闭合、松开打开。
控制器、GUI 和夹爪工作线程需要一起更新；更新包只在停止后台后部署，不自动操作硬件。
离线回归：`python -m pytest -q tests/test_gripper_toggle.py tests/test_quest_gripper_control.py tests/test_relative_motion.py`。

GUI 的“自适应输入抑抖”复选框配合“应用并暂停”使用，后台显示当前截止频率。
开关不会自动使能机械臂。未包含 `input_filter` 的旧配置默认关闭；本次随附的
`relative_control_settings.json` 显式开启，并保留原有各项参数。

配置位于 `input_filter`：

| 参数 | 初始值 | 单位/含义 |
|---|---:|---|
| position_min_cutoff_hz | 2 | Hz，平移最低截止频率 |
| position_beta_hz_per_mm_s | 0.08 | Hz/(mm/s)，速度增大时放宽滤波 |
| position_max_cutoff_hz | 15 | Hz，平移截止频率上限 |
| rotation_min_cutoff_hz | 2 | Hz，姿态最低截止频率 |
| rotation_beta_hz_per_deg_s | 0.15 | Hz/(deg/s)，角速度增大时放宽滤波 |
| rotation_max_cutoff_hz | 15 | Hz，姿态截止频率上限 |
| derivative_cutoff_hz | 2 | Hz，速度向量估计的低通频率 |

这是经过离线检查的初始配置，不是实机标定结果。输入/输出位置仍为 m，
内部速度统一换算 mm/s；旋转速度为 deg/s。XYZ 共用平移截止频率，
姿态独立按角速度调节，使用旋转短弧插值而不是逐轴 Euler 平均。

数据链路：有效性和原始突变检查 → 输入滤波 → 相对映射 → 原有规划/IK/保护。
使用同步头显采样时刻；旧 APK 明确标记为主机接收时刻。每个时刻只滤波一次，
重复快照不会继续推进滤波。缺失/倒退/过期时刻、坐标变化、原始突变均停止并要求重新接管；
不得用滤波输出刷新原始输入的新鲜度。扳机释放和故障不经过滤波。
暂停时清除滤波残留，接管初始化完成后用同一有效手柄位姿初始化滤波和相对锚点。

升级需要关闭旧 GUI 并停止其后台，再重开；接收器与控制器必须一起更新。
旧接收器缺少采样时刻时，新控制器在滤波开启状态会拒绝接管。
不自动启动/重启头显、连接机器人、使能、复位或试动。

诊断：`input_filter` 遥测/录制字段包含原始与滤波后位姿、速度估计、截止频率、
采样间隔、更新计数及滤波残差。`hand` 保留原始输入；训练 action 仍为实际下发命令。
滤波代码及相关输入代码的哈希纳入 episode 元数据。

离线检查：`python -m pytest -q tests/test_adaptive_pose_filter.py`。
合成信号对照：`python tests/benchmark_adaptive_filter.py`，不连接硬件。
滤波不能消除低频漂移、机械振动或 IK 抖动；停止后仍有收敛拖尾，不承诺完全锁位。

标准方向矩阵对应机器人 ΔX=手柄 ΔZ、ΔY=−手柄 ΔX、ΔZ=手柄 ΔY。界面支持
水平角、90°/180°预设、各轴反向和任意正交 3×3 矩阵；先观察目标预览确认方向。

1. 在预览中确认手柄追踪与目标方向。
2. 只读观察“右手食指扳机”是否随扣动/松开切换“按下/松开”。点击 **启用遥操**
   （应用列表入口或 `--controller-control` 可自动进入允许状态）。
   程序检查机器人状态及当前实际位姿的连续逆解，不要求六个 ±1 mm 方向都可达；
   仅在这些检查通过时清除历史无解警告 14，不清除机械臂错误。
3. 保持头显输入有效，松开食指扳机，再按住，机械臂从当前实际位置跟随
   手柄相对位移。每次重接管从当前实际 TCP 建立新手柄起点，不跳回会话起点，
   不再被原始 TCP 周围 ±10 mm 截断。
4. 必须一直按住扳机才能跟随，松开暂停；手柄可移动调整握姿，再按住继续，无需重新启用。
   每次继续都会重新建立相对起点，不追赶暂停期间的手柄位移。
   点击 **禁用遥操**、**停止 [空格]**、空格或 Esc 也可停止跟随。当前 B 是夹爪键，不是暂停键。
   无效追踪帧、超过 250 ms 的输入超时、超过 800 ms 的界面心跳丢失均释放控制。
   追踪恢复不自动接管，须松开扳机后重新按住。
   活跃伺服控制周期超过 50 ms 会停止并撤销允许状态，不用大步追赶遗漏周期。
5. 遥操无自动结束计时，每次接管重新建立相对起点。启动/重新允许时已经按住扳机，
   不会直接接管；先松开再按住。窗口中的禁用/停止会撤销允许状态，须重新点击启用按钮。
   高级面板内“重设起点”只释放起点，仍须新的扳机按下，不绕过实体按键。

食指扳机按下需要稳定 20 ms，松开不做去抖延迟：收到第一个松开状态即请求机器人 state 4。
state 4 是机械臂取消旧目标并停住，不表示退出遥操会话。界面显示“已暂停 · 遥操仍启用”。
停机后在最多 1 秒窗口核验 state 4 和实际关节速度 ≤0.5°/s，再锁定停稳后的保持基准。
该短窗口的平移容差在松开瞬间冻结为 `min(30,max(10,L+0.1×v+2))` mm：
`L` 是当时下发/实测位置差（不超过配置有效超前限额），`v` 是当时实速（不超过配置速度）。
静止且无目标超前时仍为 10 mm；150 mm/s、12 mm 超前时为 29 mm，而非旧固定 10 mm。
这是有界的软件诊断容差，不是物理制动距离保证；不会根据停机后的运动不断扩张。
4.5°、关节余动/安全余量以及 1 秒停稳超时保护保留，异常时再次请求停止并撤销许可。
日志 `pause_feedback` 记录停稳位移、实际使用的容差、耗时及结果，支持区分正常制动与异常。
此前暂停后约 0.7–1.5° 的残余停稳被 0.5° 外部姿态变化检查误判，新逻辑修复了这一问题。
停稳后若机械臂又被其他控制源移动，原保持检查仍会撤销遥操许可。

### 矩阵选择与跟随速度

主界面选择已保存的旧 3×3 或新 6×6 矩阵，再点击“应用我的选择”。
当前生效矩阵可在“查看当前矩阵”中展开查看；不再包含采样或验收向导。
旧 3×3 映射的平移公式为 `ΔTCP(mm) = 1000 × 手柄倍率 × M × Δ手柄(m)`，
新 6×6 映射同时补偿平移和旋转，详见下方“已保存矩阵选择”。

TCP 限速可设 1–200 mm/s、平移倍率 0.05–10×、旋转倍率 0.05–5×、关节限速 0.05–1 rad/s。
旋转限速 1–120°/s、角加速度 10–720°/s²。
平滑加速度可设 50–1000 mm/s²。GUI 修改参数会保持 `range_mm: null`，不会恢复旧小围栏。
“跟手增强”会应用平移 150 mm/s、旋转 60°/s、关节约 57.3°/s、平移/旋转加速度 600/240、平移跟随容差 12 mm，
并暂停遥操；保留当前倍率及方向矩阵。原参数备份在 `.state/relative_control_settings.before_responsiveness_20261010.json`。
TCP 限速约束命令轨迹，实际响应还受机器人反馈及关节限制影响；界面显示实际平移/角速率、
输入数据年龄、跟随误差和具体限速关节（所需速度/上限）。不同方向的关节需求不同，接近限位/奇异姿态时仍可能有速度差异。
点击“应用参数并暂停”后，参数持久化保存，并要求重新按遥操按键接管，避免改变方向或
倍率时目标跳变。

倍率控制手柄位移/转角的放大，不提高机器人的速度上限。平移采用低延迟优先策略：机器人能
跟上时按倍率映射，超速时压缩多余位移，并在明显反向时清除相反方向积压，避免手停后长时间
追赶远处目标。当前选择平移 3×、TCP 200 mm/s、加速度 1000 mm/s²，旋转仍为 0.95×。
待执行平移限制为跟随容差 + 当前命令速度²/(2×加速度)，当前配置下最高为 32 mm（相对
下发目标）；实际下发目标相对实测 TCP 的 12 mm 保护独立保留。这不是端到端延迟保证。
松开扳机或输入失效取消待跟随位移并请求停机，重新接管以当前位置建立新起点。
GUI 保留 Quest 原始 XYZ/欧拉角，另显示“对齐后手柄 ΔXYZ / Δ旋转”（机器人基座轴、未乘倍率）。
Δ旋转为旋转向量，方向代表转轴、长度代表转角；不要将它与绝对 TCP 欧拉角逐列比较。

控制循环目标 100 Hz，使用有加减速限制的连续命令轨迹；GUI 和文件遥测约 20 Hz，
避免界面/磁盘写入拖慢控制。界面显示实测控制频率、速度、跟随误差与限速原因。
WebXR 每个显示帧发送最新手柄输入；90 Hz 头显不再因旧 60 Hz 门控降为 45 Hz。
USB HTTP 连接复用、关闭小包等待，接收器向控制器即时发布，GUI 刷新独立限频。
界面“输入 ms”是输入样本数据年龄，不是手柄到机械臂的完整物理响应延迟。
命令对实测位置的允许超前距离为 `min(平移跟随容差上限, max(1 mm, TCP限速 × 0.08 s))`。
高级参数可调上限 1–20 mm，当前 12 mm；旧配置缺省保持 5 mm。
这是局部跟随距离保护，不是末端总活动范围。过小会将实际速度压低；增大则允许下发目标领先更远，
仍保留每帧速度、IK、关节、实际反馈和松开扳机停止保护。旋转超前保护保持 3°。
移除小围栏后，倍率 1× 时手柄平移 10 cm 对应末端目标平移 10 cm，不再截成 1 cm。
仍需现场确认整个运动路径净空；软件没有环境碰撞模型。不清机器人故障、不放开关节限位，
旋转限速/平滑、扳机暂停、失效停机和 SDK 保持初始化保护继续生效。
暂停期间其他控制源改变 TCP 超过 6 mm 或姿态超过 0.5° 时，需重新允许遥操。

### 初始位姿 / 采集后复位 / 异常关节恢复

主界面提供“记录初始 Pose”“检查 Pose 复位”“恢复初始 Pose”。
恢复目标是操作者记录的 TCP XYZ/RxRyRz，不是保存时的七关节角度，不要求相同关节组合。
逆解以当前关节为参考选择物理角度等价解；仍核查真实关节限位、端点 FK 和整条低速关节路径。
这不是清除故障、把所有关节设为零或保证 TCP 直线返回。
未记录初始点时不会猜测一个“安全姿态”，返回按钮保持禁用。

首次设置：

1. 先禁用遥操并让机械臂停稳，用关节恢复或 xArm Studio 调整到适合采集的姿态。
2. 点击“记录初始 Pose”，确认后只记录，不移动。已有初始点时需确认覆盖，
   不要把需要恢复的异常姿态覆盖成初始点。
3. 记录前检查关节余量、XYZ ±0.5 mm 的局部连续性；开启旋转时还检查基座各轴 ±0.25°。
   接近可达边界/局部逆解不连续的姿态会被拒绝作为初始点。
4. 初始点保存在 `relative_home.json`，TCP 为目标、实际七关节仅作历史诊断，另含有效夹爪开度及机器人/工具
   坐标配置。旧 v1 文件兼容按 TCP 读取，不需要覆盖原初始点。重启可重新载入；机器人/坐标配置不匹配或数据损坏时拒绝使用。

每次采集结束后：

1. 先松开扳机、结束并保存该次采集，再点击“禁用遥操”。
2. 点击“检查 Pose 复位”：只读求初始 TCP 的逆解，检查硬件/遥操关节余量、实际关节速度、端点 FK 和插值关节路径正解。
   该检查不清警告、不改变模式、不使能，不包含环境/自碰撞检测。
3. 查看最大关节行程及 TCP 路径包围范围；检查通过不等于路径无碰撞。
   现场确认整个机械臂的扫掠路径净空且急停可触达，再点“恢复初始 Pose”并确认。
   执行前会重新检查，初始点/当前关节改变或上次执行后必须重新检查。
4. 使用求得新关节解的关节路径；“复位速度 °/s”可设置 5–30°/s，
   加速度自动为速度的 2 倍（10–60°/s²）；不保证末端直线返回。
   控制页与采集页共用同一速度，重开 GUI 默认 5°/s。
   修改速度后重新“检查复位路径”，确认窗口显示本次速度和加速度；
   后台拒绝执行速度与已检查计划不一致的请求。这个速度不改变遥操跟随参数或单关节小步恢复速度。
   初始化先设置当前实际关节的零距离保持目标；拒绝初始化漂移、错误及模式异常。
   完成按 TCP 位置误差 <1 mm、四元数角误差 <0.5°、实际关节速度 ≤0.5°/s 判断，不匹配历史关节角。
   初始 Pose 无解/错误 FK/单段过大时拒绝执行，不偷偷回退到保存时的关节角；先用小步关节恢复调整。
5. 复位完成后停机并保持只读，不自动恢复遥操。重新启用后松开→按住扳机，
   从新的相对起点开始下一次采集。这里只提供人工复位流程，不会自动结束/写入采集器的一条 episode。

异常姿态且未记录初始点：展开“关节恢复 / 初始位姿详情”，选择 J1–J7、0.5–5° 步长，
确认后进行单关节小步恢复（固定 5°/s）。默认 2°，建议首次用 0.5–1° 并观察整臂运动。
该入口可在遥操的 5° 软余量区域内恢复，但实际关节越出硬件限位、机器人故障/保护状态时
拒绝自动运动，须按厂家流程使用示教或处理故障。单段路径超过 180° 拒绝自动绕圈。

复位期间禁止接管、修改参数、示教或重复发复位；空格/Esc、停止按钮及界面心跳超时
均请求 state 4。机械臂模式/状态改变、关节越限、轨迹偏离或超时会停止。
除已确认的关节恢复可在核查路径后清除历史无解警告 14 外，不自动清除硬件故障或解除急停。
正常夹爪保持抓持。只有显式勾选“返回初始位姿后恢复记录的夹爪开度”、启用夹爪、
初始开度和当前夹爪状态有效，才在机械臂复位完成后请求开合，注意夹手与掉落风险。

参考：[UFACTORY 运动与奇异点说明](https://docs.ufactory.cc/user_manual/ufactoryStudio/9.motion_characteristics.html)。

### 2026-10-10：上抬接近伸直姿态的提前保护

- 接管前、跟随时的实测/上一指令关节、每次最终候选指令均检查局部可解性。
  使用机器人控制器当前 TCP 正解，有限差分构造雅可比；旋转行固定以 100 mm/rad 加权。
  最小奇异值低于 20 启用方向保护；接近/不明确的方向在 8.5 前保持，
  7.5–8.5 仅允许经过前向验证的低速退出，≤7.5 禁止接管或暂停。
  这些是本项目的软件保护阈值，不是厂家认证安全边界，也不是固定高度/J4 角度限制。
- 关节起步按 2 rad/s² 限制加速；2026-10-13 改为对整组“期望速度−上一已执行速度”
  使用同一个过渡比例，不再因一个关节的小幅修正而把所有正在运动的关节反复降速。
  逐关节独立裁剪不用于这一过渡；速度差按同一比例推进。
  整体反向沿上一协调关节方向连续减速，而非插入瞬间零速帧；制动候选仍逐帧通过最终 FK、关节/空间/超前及姿态检查。
  收紧限速/目标或个别轴变向时安全制动优先，不承诺所有减速度都受软平滑约束。
  保留约 2° IK 连续性、实际关节限位和现有停稳保护。
- 姿态减速或逆解缩步期间，待跟随目标限制在当前 TCP 的有效超前距离（当前 12 mm）及
  3° 姿态邻域；丢弃多余手势并回算内部相对基准，保持扳机接管，不再因目标差超过 45 mm
  一刀切暂停。手柄保持不动不会重生被丢弃的目标，离开减速区也不会恢复旧积压。
  这是局部跟随缓冲，不是总移动范围；受限时手势行程会被截去，正常区倍率不变。
- 现在使用只读连续 IK/FK 小步探测六维手势方向，再复核平滑后的最终候选，不仅显示方向标签。
  旧临界区不再把所有方向乘到零：指标 ≤10 时的已验证退出，TCP/旋转/关节目标限速分别为
  20 mm/s、8°/s、0.15 rad/s；原配置更低时服从更低上限，最终 FK 检查仍保留原数值容差。
  这些是命令限速，不是经过认证的真机制动性能。硬件故障、关节限位和超前保护不放宽。
- 受限方向保持上一条安全指令，丢弃不能执行的手势；反向移动可在不重新扣扳机的情况下重新探测。
  如完整六维动作恶化可解性，而单独平移能退出，GUI 显示“旋转暂锁，优先平移”；
  临时锁住姿态，避免平移/旋转反复切换造成抖动，离开减速区并达到指标 22 后恢复旋转，
  或松开扳机重新接管来重新选择动作。锁定期间旋转手势被丢弃，不会在解除后突然追赶。
- GUI 显示“姿态保护/上次姿态检查”、可解性和暂停原因。保护暂停后必须先松开扳机，
  再按住从当前实际位姿重新接管；不要继续朝同一受限方向推。若当前位置已禁止接管，
  禁用遥操后使用“检查 Pose 复位”核查路径；路径不通过时按关节恢复流程处理，不能强行复位。
- 参数应用、现场净空确认后先做小幅低速测试。新保护不包含碰撞避障，不保证任意手柄轨迹
  可达，也不能代替急停。已完成历史回放、模拟及只读运动学验证，真机停止余量仍需现场验证。

方向相关限速的设计参考 [MoveIt Servo 的奇异方向速度缩放说明](https://moveit.picknik.ai/humble/api/html/namespacemoveit__servo.html)。
本项目采用自己的 FK 探测和软件阈值，不等于部署了 MoveIt 或具备其碰撞规划能力。

### 平滑后的最终目标超前检查

- 即使整组关节协调缩步，非线性正解仍需复核。下发前用正解复核最终候选，
  必要时沿上一指令到候选的关节段缩步；只有同时满足 TCP/姿态超前、步长、范围、关节限位
  和奇异姿态检查才发送。保留原超前阈值，不通过放宽保护来消除退出。
- GUI 的限速原因出现“下发目标边界回缩”表示本帧自动缩步，可继续跟随。
  若连上一指令都不能满足当前边界，则保护暂停、清掉旧目标，松开扳机后检查再接管；
  SDK 失败、计算超时或输入失效仍停止。缩步制动优先于软加速度平滑。
- `.state/relative_control_trace.jsonl` 的 `command_guard` 记录每次正解候选的超前量、
  缩步比例和通过情况，供区分平滑引起的候选越界与实际跟随异常。

### 2026-10-12：低积压跟随与连续换向

2026-10-13 当前使用低延迟优先，遥测算法标识为 `responsive-coordinated-velocity-v4`。
保留完整超速位移会积压长距离目标，因此不能同时保证超出机械臂速度能力时的完整倍率和低延迟。
`smoothing_feedback` 记录平滑前 TCP 速度、各关节期望/上一帧/平滑后的速度、
最终下发 TCP 速度及最终检查缩步比例，用于区分规划、关节平滑与实测跟随瓶颈。

- 正常可解区域也限制尚未执行的手势积压，不再让速度饱和后留下几十厘米旧目标。
  缓冲以最后实际下发的目标为中心：平移为配置超前距离 + 当前指令速度²/(2×平移加速度)，
  旋转为 3° + 当前指令角速度²/(2×角加速度)。这是待执行手势缓冲，不是新的工作空间围栏；
  最终指令与实测之间原有有效超前距离/3°检查仍独立存在，未放宽。
- 缓冲超出部分回算到相对映射基准，持住手柄不重生旧目标；明确反向的增量可清除相反方向的积压。
  反向识别忽略 ≤0.25 mm / ≤0.15° 的映射增量，以避免微小追踪噪声触发。
  平滑速度不因清除积压而置零，仍由最终已提交指令回算，协调前后级平滑状态。
- 整体关节反向沿上一运动方向按原 2 rad/s² 连续制动，正常推进采用整组速度差的协调过渡；
  制动可能继续沿旧方向一小段，并必须通过全部最终候选检查；保护需要时仍可更快停止。
- 取舍：正常速度内的小幅动作保持相对倍率；超出机器人能力的快速手势会部分丢弃，
  不承诺超速情况下保持累计绝对位移或原路径。不要用本模式替代精确离线轨迹执行。
  GUI 显示“低延迟平移 · 超速位移已压缩”时，说明手势要求已经超出当前跟随能力。
- 本轮不修改关节限位、奇异保护、碰撞灵敏度、负载、方向矩阵、初始 Pose、速度/倍率及夹爪 5% 力度。
  离线回放仅验证算法；真实机器人流畅性、抖动、制动距离和端到端延迟仍需现场验证。

### 2026-10-12：四元数姿态链路

- 控制器内部 TCP/目标/保持点使用 `[x_mm,y_mm,z_mm,qw,qx,qy,qz]`，
  姿态映射、短弧插值、平滑、限速、目标缓冲和保护误差采用四元数/旋转对象。
  角速度和小旋转增量仍是三维旋转向量，不是 Euler 分量差；平移保持独立映射。
- SDK 正解输出的 XYZ+RPY 在入口转换一次；逆解接口接收六维 XYZ+RPY，
  在调用边界转换。关节伺服接口仍接收七个关节角，不能传入七元素四元数 Pose。
- 新记录初始 Pose 的文件版本为 3，`tcp_pose_quat` 为权威目标，`tcp` 保留 GUI/旧格式兼容显示；
  两字段不一致时拒绝加载。旧版本 1/2 可读，本次不重写已保存的初始点。
- GUI“曲线 / 诊断 / 导出”显示 w/x/y/z 和相对诊断零点的测得转角；“零点”只改变诊断参考，
  不改变标定或控制。导出在原有列之后增加 qw/qx/qy/qz。主面板 RPY 仅供显示，接近
  ±180° 或俯仰 ±90° 时数值仍可能跳变，应看四元数转角而非逐轴相减。
- 本次保留原方向矩阵、倍率、扳机暂停/续控、B 夹爪及全部保护。
  四元数避免参数化歧义，但不能消除输入追踪偏差、机械臂奇异位形或真实关节限位。

  本地增量不会自动滤除虚假旋转，不能单独用来判定 PnP 误差还是参考空间混用。

切换/保存/重载和实时输入要求；`tests/test_empirical_mapping.py` 保留映射数值测试。
GTK 回归：`/usr/bin/python3 -m unittest discover -s tests -p test_pose_viewer_gui.py`。

维护升级时可用 `--adopt-lan-input` 接管同用户、本工作区、同地址的存活 LAN 桥，
避免重启 XR 参考坐标。此选项不使能机械臂；机器人/接收后台应先停止，避免重复进程。

## 独立 recorder 与训练数据格式（2026-10-15）

### 使用方法

入口与桌面快捷方式保持不变。更新代码后，需要先结束已有遥操、关闭旧窗口，
再打开新版，旧控制进程不会自动获得新数据接口。只读启动命令：

```bash
/usr/bin/python3 /home/a/xarm7-vr-lab/quest_pose_viewer.py --connect --robot-preview
```

1. 正常连接 Quest 和 xArm，核对映射后启用遥操。
2. 切到“数据采集”，填写数据集名称、父目录和任务描述。
3. 点“准备采集 / 相机预览”，等待双相机和机器人数据就绪。
4. 点“开启本条采集”：若正在有效遥操，从下一条有效样本开始记录；否则等待有效遥操。
5. 按住食指扳机、机械臂进入有效跟随后开始记录；松开即暂停，再次按住续录同一条原始 episode。
   开启录制不要求重新松开扳机，不向控制器发送命令。初始化和制动期间不记录训练样本。
6. 顾客接稳且夹爪释放后，可点“结束本条 / 判定并保存”，只冻结录制，不要求停止遥操。
   录制先冻结，再弹窗选择成功/失败及是否保留；没有默认成功，取消弹窗保持冻结，可再次打开判定。
   等待时间本身不判定成功，必须人工确认完整交付。显示的录制时长不含松扳机暂停时间。
7. 保存或丢弃之后，在采集页点“禁用遥操（复位前）”→“检查复位路径”→“返回初始位姿”。
   复用已有人工确认与路径检查；复位不由录制状态禁用，录制中显式复位会将本条标为未完成。
   保存成功不会自动运动。
   “记录 / 更新初始位姿”将当前 TCP Pose 持久保存到 `relative_home.json`，重启自动读取，可随时在停稳且无活动采集时重新记录覆盖。
8. 点“导出已保留轨迹”，默认仅成功示范，勾选“同时导出已保留的失败轨迹”可纳入失败。
   原始记录和导出均是一条任务一个 episode；失败保留与丢弃是两个独立选择。

连接、停止和录制状态在两页上方共享，各页单独滚动。相机只由 recorder 打开一次；
GUI 读取缩略图，不再次争用相机。准备采集、开始录制和导出都不发送机器人运动命令。
新采集页的任务/目录/名称输入框中空格用于文字输入；Esc 和顶部停止按钮仍有效。
关闭采集器或整个窗口时，正在录制的一条保存为 `incomplete`，不会冒充成功示范。
“丢弃”是标记 `discarded`，不会删除原始文件。每次录制用独立 ID，可安全追加至原数据集。

### 接管中途取消与真正的停机故障

遥操与数据录制独立：头显输入 → 控制器 → 被动录制订阅。不开相机/录制器也能遥操。
开启、结束、保存、丢弃、关闭录制只改变录制器，不发送机器人指令；录制判定窗口非模态，
关闭判定窗口的 Esc 不会禁用遥操。主控制窗口 Esc、停止按钮和遥操页空格仍是显式停止操作。
录制页及数据管理页控件上的空格只操作控件，不误触发机械臂停止。
录制开始可以接续已按住扳机的有效遥操；结束只冻结最后已观察到的样本边界，判定期间不追加帧。
遥操禁用、真实输入丢失、故障或复位会影响记录的连续性，录制状态不会反向决定遥操许可。

`realtime-input-v6` 将手柄数据从 Vuer 场景消息移到独立 `/unitree-controller-ws` 通道，
复用同源认证，不经过场景事件队列。最多四帧未确认，不排队重放旧位姿；确认超时重连后只发送新帧。
在途窗口同时决定速率上限（约窗口 ÷ 确认往返）：Wi-Fi 确认往返约 80 ms 时，两帧会把有效输入
压到约 25 Hz；四帧提高上限但仍只发送新帧，接收端 180 ms 数据年龄判定不变。
每个 XR 帧仍观察按键与追踪状态；释放计数、输入中断计数跨越被丢弃的中间帧，真实输入故障不能被覆盖。
Unitree/WebXR 的 motion_enabled 和暂停边沿由同一个位姿包产生，忽略旧 APK 独立的 High/Low 通道，
消除两通道先后错位。旧 APK 仍保留 High/Low 兼容行为。数据录制从不写入输入许可。
诊断中 client_version 应为 realtime-input-v6，controller_connections 应为 1；
transport 包含 in_flight、skipped、reconnects，skipped 是发送前主动丢弃中间帧，不是轨迹数据丢包统计。
此改动控制排队积压，不能消除真实 Wi-Fi 长延迟或手柄被遮挡；超过时限、XR 位姿缺失/仅为推算仍停止。

头显时钟客户端优先使用独立 WebSocket 同步；连接失败或同步响应中断时，
自动通过已认证的同源 `/unitree-clock` HTTP 接口同步。HTTP 最多同时一个请求，每秒最多一次；
WebSocket 健康后停止后备请求。HTTP 也接收“重新打开采集页”请求，避免时钟 WebSocket 不通时无法刷新。
连接建立允许等待 3 秒，但样本有效期仍为 3 秒、同步 RTT 必须不超过 100 ms；失败请求不会延长有效期。
两条通道都不可用时继续拒绝位姿，不使用电脑接收时刻伪造头显采样时刻。诊断分别保留 WebSocket/HTTP
错误和失败计数，以及所选时钟样本的来源。升级后必须退出旧的透视会话并刷新头显网页，才会加载新客户端。

v5 修正时钟校正引起的接管中断：同步往返延迟不对称时，中点时钟估计可能超前；
现在用同步区间的最早可能采样时刻检查数据年龄（中点估计减去 RTT/2），不会把旧帧判得更年轻。
接收端仍拒绝超过 180 ms 的帧和超前超过 30 ms 的时间戳；后续传输排队、追踪/前台、按键检查仍有效。
自适应滤波的 dt 使用独立的头显单调采样时刻 `sample_headset_s`，不再使用可能随校时倒退的电脑映射时刻。
原始数据同时保留两个时刻；`sample_time_source=synchronized_headset_earliest` 标明电脑时刻是保守下界，
不是更精确的曝光时间。机器人和相机的原有时间轴不变。
`unitree_input_status.json` 的 `diagnostics.timing.sample_age_ms` 保留有符号帧年龄，
错误区分“时间戳超前”和“数据过期”，便于继续排查真实网络延迟。

接管初始化需要多次 SDK 查询及零距离保持。期间松开扳机或输入暂时失效，属于取消本次接管：
发送停止、核验停稳、保留遥操许可，松开后重新按扳机即可继续。此前这个分支抛出普通异常，
会进入统一故障处理并撤销许可，表现为频繁需要再次点击“启用遥操”。
SDK 故障、GUI 心跳超时、坐标基准改变等仍保留原有停机保护。
界面增加“上次停止”原因，避免瞬时状态刷新后看不到停止原因。

单次扳机接管修复：初始化较慢（超过 250 ms）时，手柄可能一直正常发送，
但滤波器在 SDK 等待期间没有更新。初始化完成后应在最新有效位姿上重新建立滤波起点，
不能先用初始化前的旧滤波时刻检查间隔，否则第一次按住会被误判为断流，表现为需快速重按。
现在只在已通过接管初始化检查的重新建起点处允许这个正向间隔，直接使用最新原始位姿，
不带入旧滤波尾差。连续跟随中的 250 ms 间隔保护、原始位姿突变、坐标系改变、时间倒退、
数据新鲜度、扳机释放及心跳检查均保留。按下仍有 20 ms 稳定检查，随后完成保持初始化；
应一次按下并保持，松开立即停止，不要求双击。此更新仅涉及电脑端，无需刷新头显客户端。

### 三层数据，而不是一种格式绑定所有模型

GUI 的“数据管理”页复用采集页配置的原始记录父目录，支持切换其中的数据集。
默认“已保留”显示完整轨迹；“待整理”显示未完成、已丢弃及元数据异常记录；也可查看全部和回收站。
列表展示采集时间、成功/失败状态、有效时长、数据库体积和任务。选中后可拖动时间轴或播放
双相机预览，应用原相机旋转设置、跳过暂停区间，并显示片段编号和夹爪开度。
回看仅读取原始档案，不下发机械臂指令；画面采用区间内近邻帧，不代表修复了采样同步误差。

关闭采集器后，可以把选中的已结束轨迹移入回收站；恢复时移回原位置。
回收站使用同一数据集下的 `.trash/episodes`，默认导出不会扫描它；移动不改写原始数据和标签，
同名冲突拒绝覆盖。回收站不释放磁盘空间，本页不提供永久删除或批量自动清理。
正在录制、元数据异常或有未关闭数据库日志的记录不能移动。导出持有共享锁，整理持有排他锁，
防止导出过程中原始文件被移走。已经生成的导出副本不会随原始轨迹移动而删除。
数据页按需加载，扫描和预览在后台读取；播放不积压帧任务。训练导出仍使用采集页原有控件。

**第一层：原始档案 `xarm7.raw.v1`。**这是本项目的归档格式，不冒充 LeRobot 或 RoboTwin。
SQLite 标准库支持事务和崩溃恢复，原始图像按解码后的无损 PNG 存储。实际机器人反馈、
已下发动作、手柄输入及相机在扳机有效录制区间内各自按原始到达频率保存，不先缩减成训练用的 30 Hz。

```text
<父目录>/<数据集名称>/
  dataset.json
  episodes/<时间戳_唯一ID>/
    episode.json             # 任务、结果、状态、设备/相机配置、代码哈希
    raw.sqlite3              # telemetry / images / events
  exports/<格式_时间戳>/      # 从原始档案生成，原始记录不改写
```

SQLite 中 `telemetry` 表保存控制循环快照 JSON、单调时间和连续序号；`images` 表保存
相机名、相机序号、读取起止时间、宽高和 PNG BLOB；`events` 表保存录制结束等事件。
正常写入每 0.5 秒提交事务。异常断电可能损失最后一次未提交数据，未完成状态不会进入默认导出。
普通异常退出会保留已提交内容及 `incomplete` 标签。原始库不自动上传。

| 保存信息 | 约定与用途 |
|---|---|
| 实际关节 | 7 维 rad，SDK `is_real=True`；记录主机读取起止时间 |
| 实际 TCP | 基座坐标系 XYZ，m；四元数 wxyz；由实际关节 FK 计算 |
| 已下发关节/TCP | 7 维 rad / XYZ m + wxyz；成功返回后的命令及主机时间、有效标记 |
| 映射请求、限幅目标 TCP | 与已下发值分别保存，不能误作训练 action |
| 夹爪 | 实际 mm、反馈年龄；请求目标、成功下发目标、命令时间和故障分开保存 |
| Quest | 原始 XYZ m、wxyz、扳机/A/B、空间会话 ID、数据年龄、接收时间 |
| 运行状态 | 遥操许可、跟随/暂停、停稳中、复位、错误、控制频率和参数版本 |
| 图像 | 腕部 + 全局，当前配置 640×480；保留旋转前原始图像，导出应用配置的旋转 |
| 环境信息 | 相机路径、曝光/对焦请求值及读取值；方向矩阵/倍率、代码 SHA-256 |
| 机器人配置 | 启动时报告的固件版本、序列号、TCP/world 偏置、负载/重心和重力方向 |
| 任务信息 | 任务语言、episode ID、成功/失败/未标注及结束原因 |

相机内外参当前没有标定，明确保存为未知，不能假装有标定数据。电流/力矩、深度和硬件曝光时间
当前没有采集；以后增加传感器时应升级归档 schema，不用零值代替缺失测量。
PNG 是对相机输出解码后的无损保存，不能恢复设备 MJPG 编码前已经损失的信息。
两路 640×480×30 FPS 的未压缩像素量约 55 MB/s，PNG 实际体积随画面变化；磁盘需留足空间。
不足 2 GiB 拒绝开始新条，不足 1 GiB 将当前条保存为未完成。

**第二层：默认训练导出 LeRobotDataset v2.1。**采用官方 0.3.3 所定义的文件布局和元数据，
导出器不调用本机 v3 的 `LeRobotDataset.create()`，避免静默写成 v3。

```text
meta/info.json                         # codebase_version = v2.1
meta/tasks.jsonl
meta/episodes.jsonl
meta/episodes_stats.jsonl
data/chunk-000/episode_000000.parquet
videos/chunk-000/observation.images.cam_high/episode_000000.mp4
videos/chunk-000/observation.images.cam_left_wrist/episode_000000.mp4
alignment/episode_000000.jsonl          # 每训练帧对应的原始样本/图像序号与时间偏差
export_manifest.json                   # 原始文件指纹、动作空间、对齐/暂停策略
```

默认 `observation.state` 和 `action` 均为 8 维：
`[joint_1 ... joint_7, gripper_open_fraction]`，关节 rad，夹爪实际开度或已下发开度除以 84 mm，
0=闭合、1=张开。action 取成功下发的关节目标，既不是 Quest 坐标，也不是限速前的理想目标。
不伪造 ALOHA 的 14 维双臂数据。无新夹爪命令时维持最近成功下发目标；首次命令之前用实测开度。
需要注意：SDK 命令成功只表示接口接受，不表示实体已经到达目标。

默认视频为 H.264、yuv420p、CRF 18，原尺寸；原始 PNG 始终保留。
全局相机映射 `cam_high`，唯一腕部相机映射 `cam_left_wrist`，这里只是模型输入名称，
不表示存在左/右两个机械臂。数据集中不保存伪造的右腕图像。
task_index 对应真实任务文字，帧索引、全局索引、episode 索引、均值/方差等按 v2.1 保存。

**第三层：模型适配。**`openpi_xarm7.py` 提供官方 OpenPI 输入/输出变换和 `make_training_config()`：
双相机 RGB、8 维 state/action、缺失右腕图像的 false mask；模型内部再补至 32 维。
默认数据保存绝对关节目标；训练配置对前 7 维做相对当前状态的 delta，夹爪保持绝对开度，
输出使用配对的 AbsoluteActions 还原。不要同时使用 `joint_delta` 导出和这个默认 delta 变换。
不要直接使用 ALOHA 6+1 双臂掩码或 DROID 的机器人归一化统计。

在选定的 OpenPI checkout 中，将此模块放入可导入路径，在 `training/config.py` 的
`_CONFIGS` 列表构造完成后、`_CONFIGS_DICT` 创建之前加入：

```python
from openpi_xarm7 import make_training_config
_CONFIGS.append(make_training_config("local/my_xarm7_dataset", batch_size=8, action_horizon=30))
```

将导出目录置于该 OpenPI 环境的 `HF_LEROBOT_HOME/local/my_xarm7_dataset`，按该 checkout
官方说明先运行 `scripts/compute_norm_stats.py --config-name pi05_xarm7`，再运行训练入口。
配置使用 `pi05_base`；30 Hz、horizon=30 对应 1 秒动作序列。batch_size=8 只是起始配置，
未测试本机 π0.5 显存/训练速度。模型仍需安装、训练和真机部署接口验证；本次不自动启动训练。
变换的 RGB、维度、缺失相机 mask 已离线测试，OpenPI 完整训练工厂尚未在实际 OpenPI 环境执行。

### 时间同步、暂停与数据质量

- 控制循环仍以原目标 100 Hz 运行，GUI 仍约 20 Hz；新线程通过有界队列和非阻塞 Unix
  datagram 发布记录，不在控制循环等待录制器。录制端保存序号并检查丢包。
- USB 相机没有硬件同步。保存的是主机读取完成时间，不是曝光时间；SDK 反馈也可能有设备缓存延迟。
  导出以 30 Hz 网格选最近机器人样本（≤25 ms）和相机帧（≤40 ms），每帧偏差保留在 alignment。
  这些阈值只限制主机时间偏差，不保证真实曝光/运动误差达到相同值。
- 原始机器人或图像序号缺失、时间间断 >100 ms、图像复用超过 10%、夹爪反馈年龄 >0.75 s 等
  会拒绝默认导出，而不是复制旧测量凑成合格数据。必要时可选 15/20 Hz 导出，原始数据不损失。
- 当前夹爪仍约 2 Hz 实测；没有提高控制总线负载。训练帧使用有新鲜度上限的保持采样，
  完整保留实际更新年龄。如果后续任务依赖细粒度夹爪动态，应先测量并升级夹爪反馈频率。
- 新录制采用 `capture_mode=trigger`：松开扳机只暂停，不结束**原始 episode**；暂停期间不写入
  图像/关节样本。相机继续预览，图像按采集时间归属区间，避免延迟编码的暂停图像混入续录。
  `capture_intervals` 保存各次有效录制的真实起止时刻，机器人样本另带 `capture_segment`。
  区间之间的序号跳跃属于主动暂停，区间内丢包仍视为质量问题。
- 导出将同一条原始 episode 的有效按压区间按顺序拼接为一个 Parquet 和每相机一个 MP4。
  `timestamp` / `frame_index` 是去掉暂停的连续播放时间；`source.monotonic_s` 保留真实时间，
  `capture.segment_index` / `next.discontinuity` 标明内部间断，alignment 保留源帧编号。
  过短或缺帧的按压区间会拒绝导出，不静默删除末尾再把成功标签贴到前一段。
  旧版制动区间仍不构造虚假动作，但有效区间归入同一个导出 episode。
- **训练读取须遵守内部边界**：标准 LeRobot loader 仅按 episode 边界填充，不自动认识暂停。
  `export_manifest.json` 的 `training_windows` 给出每个连续窗口 `[from_frame,to_frame)`。
  可在完整 LeRobotDataset 配置好 delta_timestamps 后调用
  `recording_training.restrict_training_windows(ds, export_root, horizon=30)`，
  再交给训练 DataLoader；如查询历史观测，需设置 `history`。不跨暂停，不拆磁盘 episode。
  `openpi_xarm7.make_training_config()` 仅提供模型变换；接入其实际训练 loader 时也须应用上述筛选，
  不能仅注册该配置就认为已处理暂停边界。STEAM 帧对同样不能跨 `training_windows`。
- LeRobot v2.1 结果：只有最终记录行 `next.done=true`；成功时该行 `next.success=true`，
  失败时为 false。`annotation.success_valid` 仅在已标注末帧为 true，区分旧未标注记录与失败。
  两个 `next.*` 名称沿用 [官方 v0.3.3 评估实现](https://github.com/huggingface/lerobot/blob/v0.3.3/src/lerobot/scripts/eval.py)，
  并非格式强制自带字段；本项目在 features 中显式声明 bool。人工事后结果赋给最后有效记录行，
  不假称测出了实际成功发生时刻，不生成未经定义的 reward，也不伪造终止后的动作。
  `meta/episode_annotations.jsonl` 和原始 `episode.json` 保留结果、人工审核时间和保留选择。
- 录制中修改遥操参数、重启控制会话、进入复位或控制故障，会将当前条标成未完成。
  手柄追踪、时钟同步或输入有效性短暂中断时，机械臂仍立即停止，本条采集保留为“输入中断”。
  异常区间不写入遥测和图像；恢复后的有效输入必须先观察到松开再按下，才续录新的片段。
  恢复前发生的松开计数不能直接授权续录。再次接管前可等待或结束本条并人工判定。
  `input_interruptions` 及 SQLite 事件保存中断原因和恢复时刻，界面持续显示最近原因；
  录制器还保存输入无效计数及原因，避免短暂异常被后续正常状态掩盖。
  机器人遥测超时、相机中断、磁盘不足、停止采集/关闭进程仍保留原有结束规则。
  已松开暂停后摘头显不会结束本条；人工判定期间已冻结，不再追加数据。
  录制器失效不会阻塞遥操，GUI 会显示录制状态超时，机械臂原有停止/心跳保护继续负责控制安全。
- 只有整个导出成功才把 `.partial` 目录改为最终名称；失败清单保留，已有目录不覆盖。

### 命令行导出与 RoboTwin 对接

日常使用采集页按钮即可。命令行可调整动作空间/帧率，以下路径替换为自己的数据集：

```bash
/home/a/download/lerobot/.venv/bin/python export_recording.py \
  /path/to/raw_dataset /path/to/new_v21_dataset --format lerobot21 --fps 30

# 原始值不变，重新生成关节增量训练视图：
/home/a/download/lerobot/.venv/bin/python export_recording.py \
  /path/to/raw_dataset /path/to/new_delta_dataset --action-space joint_delta

# 末端位姿视图：XYZ(m) + quaternion(wxyz) + gripper，共 8 维
/home/a/download/lerobot/.venv/bin/python export_recording.py \
  /path/to/raw_dataset /path/to/new_tcp_dataset --action-space tcp_pose

# 当前 OpenTeach 环境已有 h5py，导出 RoboTwin / XPolicyLab 原生 HDF5：
/home/a/miniconda3/envs/openteach/bin/python export_recording.py \
  /path/to/raw_dataset /path/to/new_robotwin_dataset --format robotwin
```

`--include-unsuccessful` 显式纳入未标注/失败的完整轨迹，但不会纳入 incomplete/discarded。
其他模型（ACT、Diffusion Policy、SmolVLA 等）可选择关节或 TCP 导出，并在各自适配器转换单位、
图像尺寸、时间窗口和状态特征；不需要改变原始档案。LeRobot v3 的训练代码需另行使用其官方
v2.1→v3 转换工具，不能把版本字符串直接改成 v3；本次提供的是实际 v2.1 导出。

RoboTwin 导出目标明确为当前官方的 **XPolicyLab / xspark v1.0 HDF5**，不是旧版双臂原始布局。
每段写为 `data/episode_0000000.hdf5`，包含 instructions、state、action、vision 和 timestamps。
state/action 保存 `joint_states` 7 维、`ee_joint_states` 1 维；为兼容当前官方 v21 转换器
硬编码的字段名，额外提供指向同一数据的 `left_arm_joint_states` / `left_ee_joint_states` HDF5
硬链接。没有右臂；`xarm7_profile.json` 明确 `arm_dim=[7], ee_dim=[1]`。
全局图像为 `vision/cam_head/colors`，腕部为 `vision/cam_left_wrist/colors`。
图像用官方 `encode_image_bit` 编码，带 RGB 标记；第三方源码和 SHA-256 位于
`third_party/robotwin_image_codec/`。不能自行用普通 JPEG 替换而忽略通道约定。

使用 XPolicyLab 通用转换器时，还需在其机器人/环境配置登记这个单臂维度、相机和 30 Hz；
它当前会为缺失右腕生成空图，所以本项目优先直接导出 v2.1 并由 OpenPI 适配器标记缺失相机。
不能不改配置就使用 RoboTwin 的 ALOHA 双臂训练或执行接口。本项目没有创建伪造的双臂示范。

官方依据（核对日期 2026-10-14）：

- [RoboTwin 数据与 XPolicyLab 转换说明](https://github.com/RoboTwin-Platform/RoboTwin)
- [XPolicyLab v2.1 转换器](https://github.com/XPolicyLab/XPolicyLab/blob/main/scripts/transform_lerobot_v21_format.py)
- [LeRobot 0.3.3 / v2.1 读取器](https://github.com/huggingface/lerobot/blob/v0.3.3/src/lerobot/datasets/lerobot_dataset.py)
- [OpenPI 自定义数据配置](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/training/config.py)

离线验证覆盖真实官方 v2.1 读取器（LeRobot 0.3.3 + datasets 3.6.0 隔离在 `.state/v21_validation`）、
TorchCodec 视频读取、8 维 state/action、动作序列及末尾 padding、RoboTwin 官方图像解码、
模拟 recorder 生命周期、原有遥操与 GTK 回归。没有使用合成数据驱动机器人。
尚未完成本机双相机与实体机械臂同时录制的现场验收，也未执行 π0.5 训练。


## 数据检查、清洗与导出

“数据管理”页集中提供检查、报告和导出。操作作用于所选整个原始数据集，列表的浏览筛选不影响导出范围。默认 15 FPS、仅成功且完整保留的轨迹；可勾选纳入失败轨迹。CLI 保留原有 30 FPS 默认，建议显式指定 `--fps 15`。帧率必须按实际相机采样选择，降低帧率也不能修复缺帧或短按压。

- “检查数据”：逐条检查，不生成训练视频；报告写入 `quality_reports/` 的独立目录。
- “清洗导出”：跳过不合格的整条轨迹，在新 `exports/` 目录生成 LeRobot v2.1 或 RoboTwin HDF5，同时保留 JSON 和可读文本报告。未勾选时遇到不合格轨迹中止。
- 原始 SQLite、PNG、人工成功/失败标签不修改。缺失数据不补造；不自动裁掉坏尾段再把成功标签移到较早片段。未完成、录制中、丢弃和回收站轨迹不纳入。
- 检查原始机器人样本（包括降采样后未选中的帧）、连续性、遥操有效状态、夹爪反馈、时间对齐、实际输出图像的解码和尺寸、重复帧、跨片段会话/参数一致性。参数型告警不等同于任务成功质量判定。
- SDK 观测读取/发布时间偏差、输入延迟等作为报告警告展示，需人工复核；当前图像对齐仍基于主机记录时间，不是硬件同步。检查通过不代表轨迹动作质量或任务标签自动验证通过。
- 一条原始任务仍导出一个 episode；暂停不补帧，`source.monotonic_s` 保留源时间，`next.discontinuity` 和 `training_windows` 标明边界。训练的动作窗口应使用 `recording_training.restrict_training_windows`，避免跨越暂停。
- 导出始终重新检查源数据，不盲目信任旧报告。失败目录保留 `.partial` 和错误/质量报告，不作为成功数据集。不会覆盖已有目录。

命令行示例（目标目录必须不存在）：

```bash
python export_recording.py RAW REPORT_DIR --scan-only --fps 15
python export_recording.py RAW EXPORT_DIR --format lerobot21 --fps 15 --clean
python export_recording.py RAW EXPORT_DIR --format robotwin --fps 15 --clean --include-failures
```

检查/导出以独立低优先级进程运行，不调用机械臂 SDK，不发送遥操停止、使能或复位命令。

### GUI 布局与操作流程（2026-10）

界面分为“遥操控制 / 数据采集 / 数据管理 / 设备诊断”四页。连接、启用、禁用、停止及连接状态常驻顶部。原有快捷键规则保留：任务输入框可输入空格，停止按钮一直可见。

- 遥操控制：左侧实时手柄、目标、下发和实测位姿及复位；右侧常用倍率、速度、抑抖、夹爪。更多参数、按键映射和关节恢复折叠显示。参数修改会提示“未应用”，收到后台新参数版本才显示已同步；仍使用原“应用并暂停”行为。
- 数据采集：数据集/目录设置折叠；任务、相机准备与关闭、本条开始/判定分区。预览按比例限制在 400×300 内，仅在文件变化时解码；状态超时或关闭后清除旧图。复位按钮沿用同一控制器和速度设置。
- 数据管理：左侧轨迹列表和回收站操作，右侧双相机回看及时间轴；检查、报告和导出置于列表上方。默认 15 FPS、清洗导出、排除失败轨迹；可显式包含失败轨迹。列表筛选仅影响浏览，检查/导出仍作用于所选整个数据集。
- 设备诊断：头显地址/配对、重启/唤醒/检查、停止接收、旧映射/新矩阵选择、诊断零点、位置 CSV、曲线及完整状态。

`quest_dashboard_layout.py`、`quest_recording_layout.py` 只负责布局；`quest_ui_state.py` 集中计算数据操作按钮状态，不读取或改变机器人控制状态。状态过期、正在等待采集器确认或检查/导出时，阻止互相冲突的数据操作；采集器无响应时仍能关闭。数据集读取失败不会继续使用旧选择导出。跟随、滤波、按键、复位安全检查、记录和导出格式的后台实现保持不变。

无显示环境可使用系统 Python 运行 `test_dashboard_structure.py`、`test_gui_workflow.py`、`test_export_ui_logic.py`。结构测试使用控件树替身，不等同于真实 GTK 渲染验收；在桌面会话可运行 `test_pose_viewer_gui.py` 做真实控件测试。
